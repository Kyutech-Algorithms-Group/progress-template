# 研究進捗リポジトリ

自分の研究の進捗報告と議事録を貯めていくリポジトリです。
報告は、AI（ClaudeまたはChatGPT）に `AI_MANUAL.md` を読ませて書かせます。自分で形式を覚える必要はありません。

毎日24時に、先生のClaudeがこのリポジトリを読み、研究室のNotionに転記します。毎週月曜には、その内容から週報が作られます。

---

## 1. 最初に1回だけやること（初期設定）

初期設定は、AIに `SETUP.md` を読ませると順番に案内してくれます。AIに次のように頼んでください。

```
次のURLの SETUP.md を読んで、それに従って研究進捗リポジトリの初期設定を手伝ってください。
https://github.com/Kyutech-Algorithms-Group/progress-template/blob/main/SETUP.md
```

AIが「URLを開けない」「読めない」と答えたときは、ブラウザで上のURLを開き、ファイルの右上のコピーボタン（Copy raw file）で中身をコピーして、上の依頼文と一緒にAIに貼り付けてください。

AIは次のことを案内します。

1. 自分のリポジトリを作る（Kyutech-Algorithms-Group に `progress-<自分のGitHubアカウント名>`、**Private**）
2. AIから自分のリポジトリを使えるようにする（Claude や ChatGPT の GitHub 連携）
3. `tasks.md` に氏名・GitHubアカウントと、いまの課題を登録する
4. Notionの「2026年度メンバー」の自分の行に、GitHubアカウントとリポジトリを登録する（登録すると、毎日の転記が始まります）

---

## 2. 報告のしかた

進捗があったときに、いつでも報告してかまいません。

### ① AIにこう頼む（コピーして使ってください）

```
Kyutech-Algorithms-Group/progress-<アカウント名> の AI_MANUAL.md を読んで、それに従って進捗報告を登録してください。
```

### ② 伝えること

- **必ず伝えること**：どの課題についてか（新しい課題なら「新しい課題」。ある課題の一部なら「〇〇のサブ課題」）、行ったこと、次にすること（終わったら「完了」）
- **あれば伝えること**：わかったこと、相談事項、期限や期限の変更

内容が大まかなときは、AIから1回だけまとめて質問があります。新しい課題のときは期限、期限のある課題のときは期限の変更についても聞かれます。わからなければ「なし」と答えれば大丈夫です。

### ③ より良い報告のために

- 「修正した」「実験した」だけでなく、**何に対して、何を、どうしたか**を伝える（例：どの査読コメントにどう対応したか、実験の条件と結果の数値）。
- **生成AIを使って作業したとき**は、その作業をした会話の中でそのまま報告を頼むのがおすすめです。AIが作業内容から報告をまとめます。

### ④ AIが直接書き込めないとき

普通のチャット画面のAIは、GitHubに直接コミットできないことがあります。その場合、AIがファイル名と中身を示すので、GitHubの画面で **Add file → Create new file**（`tasks.md` は鉛筆マークで編集）から貼り付けてコミットしてください。

---

## 3. 議事録

議事録は報告の1つとして、自分の分だけを登録します（3人同時のミーティングでも、1人ずつ自分のリポジトリに）。

```
Kyutech-Algorithms-Group/progress-<アカウント名> の AI_MANUAL.md を読んで、次の記録から私の議事録を作ってください。
議事録：〇月〇日 〇時〇分のグループMTG（個別MTG）
（ここに文字起こしやメモを貼る）
```

ほかの学生の発表が含まれていても、AIが自分の分だけをまとめます。聞き取れなかった箇所は【要確認】と書かれるので、確認してAIに直してもらってください。

---

## 4. 直したいとき・間違えたとき

- **内容を直したい**：「〇月〇日の報告の〇〇を直して」とAIに頼む。Notionにも翌日反映されます。
- **登録ミス**：ファイルを自分で消さず、「〇月〇日の〇〇の報告は登録ミスなので取り消して」とAIに頼む。AIが報告に「登録ミス」の印を付け、課題一覧の変更を元に戻します。登録ミスの報告は週報に載りません。

---

## 5. エラーが出たとき

転記のときに書式の問題などが見つかると、そのファイルは転記されず、研究室の Notion の「報告・記録」に、種類「エラー」、タイトル「エラー：ファイル名」の行が作られます。

- 報告を書く前に、Notion の「報告・記録」で、自分のエラーが残っていないか確認してください（タイトルが「解決済み」で始まるものは対応済みです）。
- エラーの行には、何が問題かと直し方が書いてあります。直し方がわからなければ、その内容をAIに貼り付けて「このエラーを直して」と頼んでください。
- 直すと、次の転記（毎日24時）で正しく転記され、エラーの行のタイトルに「解決済み」が付きます。自分で Notion を書き換える必要はありません。

---

## 6. 注意すること

- `README.md`、`AI_MANUAL.md`、`SETUP.md` は書き換えない。
- 課題の「停滞」は先生がNotionで付けます。`tasks.md` には書かない。
- 課題の中にサブ課題を作れます（何段でも可）。「〇〇のサブ課題として△△を追加して」とAIに頼んでください。
- ほかの学生のリポジトリは、見てかまいませんが書き換えない。
- 2週間以上報告がないと、週報で「要フォロー」になります。
- 困ったときは周りと相談する。
